## 1. How the cohort was built

1. The round-4 script `build/freeze-cohort-r4.js` is run unchanged in a sandbox whose writes go to memory (it rebuilds rounds 3, 2 and 1 the same way). Its 432 round-4 outputs were compared with the files under `r4/` on disk: 432 of 432 byte-identical (the build stops on any difference). Its 143 records are the base; no record is added or removed and every cohort role is kept (no unseen slots).
2. The round-4 packet issues P4-1…P4-4 are applied (section 3). No capture file is added: P4-1 removes non-G1 directions, P4-2 and P4-3 re-type and annotate captured lines, P4-4 re-derives one packet field.
3. Opaque ids: `sty-` + 10 hex of SHA-256(`styling-inci-v1.0-cohort-5/opaque-id/` + slug). No round-5 id equals a round-1, -2, -3 or -4 id (checked). The slug ↔ id map (with the round-1…4 ids) lives only in `r5/cohort.json` (`id_map`, `records[].source_slug`, `records[].history`).
4. Versions: every record carries `standard_version: styling-inci-v0.5` and `lexicon_version: styling-lexicon-v0.5`. The v0.5 rule and lexicon changes (R4-Q1…R4-Q7, RG4-*) are rules for the lanes, not data changes; no frozen value was edited for them.
