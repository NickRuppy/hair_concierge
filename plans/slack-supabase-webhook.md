## Chosen direction

Supabase database webhook (pg_net after-commit HTTP) invokes a small Supabase Edge Function for a queued Slack delivery. It reads authoritative event/profile data via service-role RPC, claims one row atomically, formats the existing Slack blocks and posts to the existing Slack webhook. No Vercel route, cron, Slack credential, or Slack dispatch remains. A Supabase pg_cron database-only sweep runs each minute to reconcile missing eligible queue rows and wake only due or stale work; zero edge invocations while idle. No database network wait inside a billing transaction. Notification failures must not roll back billing.
