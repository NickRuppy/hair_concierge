## Chosen direction and scope

Use one POSIX Python launcher (`scripts/verification/run.py`) with a kernel file lock in the user's cache directory, shared across all worktrees and apps. Keep the lock file permanently; the OS releases the lock on process exit. Gate leaf test, build, typecheck, and lint commands. Node test mode preserves process isolation and existing imports while limiting file concurrency to two (configurable explicitly; GitHub Actions preserves native worker concurrency unless explicitly overridden). Heavy database runs can request one worker. Reject nested launcher use with an actionable error rather than deadlock. Forward cancellation to the job's process group and enforce a bounded runtime. Do not change test assertions or product behavior.

Keep composite verification scripts ungated; each leaf takes the shared slot. Route the nested Personal Plan test launcher through the same runner. Add a focused `test:focused` command accepting explicit file paths and the runner's own low-memory process-level tests. Keep CI's complete contract coverage intact and expose manual workflow dispatch. Do not automatically infer affected tests or remove required coverage.

Update repository and personal Codex/Claude instructions to require focused iteration, one final owner of broad verification for the same content/environment, and no heavy reruns by advisory reviewers without new evidence. Install a user-owned launcher for raw heavy commands from older worktrees. Launcher limitations must be explicit: existing unguarded jobs and commands bypassing it remain outside enforcement.

Prepare a separate opt-in Hetzner runner for explicit focused Node test files only. Transfer a committed source archive without environment files or host credentials; fail on dirty tracked content to avoid testing the wrong tree. Isolate installation/execution in Docker, one job at a time, with 1 CPU, a 1 GiB memory cap and no additional swap, a timeout and no network during tests. Never mount production paths or the Docker socket into the container. Full suites/builds/typechecks remain in GitHub CI because the existing 4 GiB server also runs Vinted, price audit, and Product Intake. Remote activation depends on Nick's response after capacity reporting; preparation is independent.

Investigate retained local Mac helpers read-only; no Hetzner process cleanup is in scope. Cleanup requires evidence that a process is abandoned; age or high counts alone do not establish that. Record what can and cannot be safely reclaimed.
