## Designed user journey

1. A new scanner-ad visitor follows `/lp/scan`, retains scanner campaign attribution, and immediately sees quiz question 1 with the short approved explanation. A visitor with saved quiz progress resumes at the saved step; returning to question 1 preserves the existing explanation-dismissal state.
2. The existing quiz and lead/preparation steps run unchanged, including present scanner inserts, back navigation, invalid-email correction, saving and retry behavior. A package/session lookup failure does not silently switch the visitor to the organic offer or reset progress.
3. Eligible non-paying scanner visitors see the locked result/offer, personalized from their answers: profile and diagnostic visualization → scanner explanation/photo → real example scan with enlargement → concise outcome → captioned Steffi video → trial timeline and shared tariff selection → app benefits → customer quotes → FAQ/legal footer. Already entitled/partner/test users keep their existing routes and are not newly paywalled.
4. Both offer shortcuts jump to pricing. Annual is preselected; changing interval updates the authoritative first-charge and renewal terms. The selected plan opens the existing checkout. Trial unavailability, prior trial use, failed or abandoned authorization and provider recovery retain existing behavior; never unlock access based on the redirect alone.
5. After verified authorization, existing readiness/provisioning leads to `/scan?welcome=scan`. Retry/recovery behavior remains in the existing flow. The day-5 promise only ships once actual eligible trial-relative reminder delivery is verified for both providers.
6. WhatsApp remains visible separately above the bottom purchase bar. During local implementation it explicitly says the contact is not configured; once a real destination is provided it can open that contact on user action. No message is sent automatically.
