## Chosen behavior

1. A pure `recommendLocalChecks(files)` in `scripts/verification/local-checks.mjs` returns `{status, nodeTests, commands, unmappedPaths, notes}`. Status is `focused`, `docs-only`, `owner-review`, or `no-changes`. Recommendations protect focused iteration, not complete release coverage. Commands are argv arrays, ordered and deduplicated; nothing executes automatically.
2. Seed only known owner seams, backed by direct test imports: questionnaire normalization/primary-concern -> questionnaire owner tests; Personal Plan question-path -> both question-path/module contracts; candidate ranking -> its comparator contract; category capture queue -> its queue contract; Stripe checkout-session params and checkout attempt -> their exact Node contracts. Changed `.test.ts`/`.test.tsx` files can recommend themselves. Unknown `.spec.ts`, fixtures, migrations, package/lock/config and unrecognized source paths remain in `unmappedPaths` and require owner review. Mapped `.spec.ts` leaves are allowed only when known to be Node contracts.
3. Markdown guidance/docs/plans/AGENTS/CLAUDE changes recommend reference/format review and `git diff --check`, not application suites. CI path classifier/workflow changes recommend their existing focused CI contracts. Verification runner/input changes recommend `npm run test:verification-runner`; planner changes recommend its own `tests/local-check-plan.test.ts`.
4. `scripts/verification/plan.mjs` collects committed branch changes against an explicit `--base` (default origin/main), plus staged/unstaged changes and untracked files. Use NUL-delimited Git output, validate the base as a commit, include both sides of renames/deletions, and fail nonzero on Git/diff errors. `--files <paths...>` supports explicit exploration without Git; incompatible/empty explicit arguments fail. `--json` emits the pure result with scope metadata; text output shell-quotes argv safely for copying. Missing mapped test files become owner-review gaps. No diff or an empty diff is never a verification waiver.
5. `coding-check --status` is read-only and reports `idle` or `running` with the current supervisor PID, cwd, command basename and start timestamp when known. Kernel-lock state is authoritative; stale metadata after a killed supervisor must not report a running job once the lock is free. The launcher writes a small atomic metadata sidecar only while actually holding the slot, clears it after cleanup, and never records arguments or environment. Emergency bypass jobs do not overwrite another owner's metadata. Older launchers may yield running/owner-unavailable status. Remote jobs are outside this local status command.
6. Add `verification:plan` npm command and concise guidance to inspect the plan and active owner before choosing focused work. Reuse valid receipts for unchanged content/environment; wait for the existing owner rather than launching a duplicate broad check. The status command informs coordination; it does not automatically reuse results, cancel sessions, or coordinate source edits.
