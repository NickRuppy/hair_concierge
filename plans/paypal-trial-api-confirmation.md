## Integration review correction

Parent identified a stale-read race in the original JavaScript late-event expiry check: an unproven attempt read could be followed by a competing API proof, then unconditional reserved-enrollment denial would cancel that valid proof. The webhook now delegates the decision to the same serialized pin transaction. After verified event/binding validation and immutable evidence insertion, a late event with no existing proof blocks only a still-reserved enrollment and marks neutralization required. It returns the unproven row; ordinary reconciliation performs the already-existing cancellation cleanup. A stored proof always wins and is never denied by a later event. This preserves the approved fallback/expiry semantics rather than introducing a new policy. App interleaving and actual two-session SQL tests cover it.
