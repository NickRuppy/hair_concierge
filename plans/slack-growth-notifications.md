## Designed user journey
1. Nick opens private #growth. Only invited members can view the messages; the webhook is scoped to that channel.
2. A verified trial activation creates **Trial gestartet**, with account name (when present), email, plan, payment provider and actual trial end.
3. The first successful payment after a trial creates **Trial konvertiert**, with identity, amount/currency, plan and provider. A direct purchase uses **Neukauf**. A missing name shows email alone; if profile temporarily cannot be read, retry. A permanently absent/deleted identity must show an explicit unavailable label and stable user ID rather than invent an email; this rare fallback is part of sign-off.
4. **Nutzerverwaltung öffnen** opens the existing protected admin users list. It does not bypass authentication or select a specific row.
5. On Slack/network interruption, the payment flow remains successful and the notification is retried automatically. Delayed messages include their original event time. Five unsuccessful attempts or permanent Slack failure produce a sanitized operational error for monitoring and manual recovery, not a customer-visible failure.
6. Repeated provider delivery does not create another queue row for the same canonical event. Incoming webhooks cannot guarantee exactly-once display if Slack accepts a message and the response/DB receipt is lost; rare duplicates remain possible. Renewals and test traffic are quiet. Existing events are not flooded into the channel at first activation.
7. Channel notifications are set to All new posts. Slack currently reports account notifications snoozed; this is a separate existing user preference and is left unchanged.
