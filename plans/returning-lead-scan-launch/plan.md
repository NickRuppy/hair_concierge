# Returning quiz leads → scanner trial (implementation plan)

Status: **implemented and locally review-ready in the task worktree; unpublished**. All known product and journey decisions are confirmed. No production campaign send, migration, feature activation, or deployment is authorized by this plan. Base: `origin/main` at `7072124b` on 2026-09-18.

## Outcome and boundaries

A prior quiz lead receives a person-specific email link. It opens the **ordinary quiz at its first question** and, when a completed quiz is recognized, shows a compact two-choice dialog over that screen. **Continue always goes directly to the existing scanner-focused result/offer page**, without any more quiz questions before the offer. Edit walks the regular quiz with saved answers prefilled, saves a new completion, and generates a fresh result/offer on that same scanner page. Only after confirmed trial/paid access, ask any genuinely missing profile facts (hair length when it is the sole gap; potentially more for older submissions) before the first personalized scan. The email link itself never grants account or trial entitlement.

The return capability must work in principle for every person with a completed quiz, regardless of when it was submitted; Customer.io owns selecting the recipients eligible for the Sunday send. Attribute trials and purchases reached through this reminder to the **Customer.io reactivation email**, not the lead's original acquisition channel. Keep historic acquisition/offer sessions immutable as background history; a dual-touch launch report is not required. Do not silently turn a prior organic or Personal Plan purchase into `scan_v1`, skip billing eligibility, or make the entire quiz mandatory for a usable saved lead. Shipping, sending, and production activation are separate authorizations.

## Proposed journey and planning evidence

1. For a person with more than one completed quiz, select their **most recently completed submission**, regardless of regular or Personal Plan quiz kind; an older quiz is retained, not overwritten. The individual email credential is bound to that exact selected lead when the link is generated, so a later submission cannot silently change what an already-sent link opens. Email contains that bounded credential at a `/quiz/return?token=…` entry. The server validates it before client analytics/UI render, strips it from the URL via redirect, and keeps only a scoped HttpOnly return context. Disable Customer.io click tracking and automatic URL parameters on that CTA; no token is logged or sent to analytics. GET/previews do not consume the credential or create a measured funnel session.
2. The existing `/quiz` first question appears, with a **small dialog over it**: “Mit meinen Antworten weiter” or “Antworten bearbeiten.” See the [revised contextual proposal](experience-preview.html); local desktop/mobile captures were reviewed but are ignored by Git. No new return page or separate failure page. The dialog discloses no name/email and does not claim that an account has been authenticated. The dialog is keyboard/focus accessible and cannot be accidentally bypassed into an unrelated draft.
3. Continue uses the exact selected completed lead and immediately opens the **existing `scan-regal-v1` scanner-refined result/offer** at `/result/[leadId]`, even if the saved source has gaps. No extra quiz questions appear before this offer and no new quiz completion is recorded. The offer shows only supported profile facts, never invented answers. Edit seeds the regular quiz with available saved answers, walks the existing questions, persists a new lead/completion, and regenerates the result/offer from the new answers on the same scanner variant. New email-return attribution/session binds the exact selected/new lead without mutating historical sessions. Returning-lead metrics distinguish return/continue/edit, offer view, checkout, confirmed trial/purchase, and scanner arrival without fabricating a new quiz completion for Continue.
4. No sign-in occurs on link arrival, quiz prompt, or offer view. The visitor selects the regular seven-day trial offer and then completes the necessary account/email verification during the start-trial handoff; only a confirmed eligible identity can actually enroll. After provider confirmation/access, `/plan-bereit` asks only genuinely missing profile facts, then opens `/scan`. Hair length remains the sole question for leads missing only hair length; older incomplete submissions may need more than one fact. Invalid or expired return credentials use the normal quiz start with a small non-blocking explanation and a safe fresh-quiz path, rather than a custom error page; temporary lookup failure does not claim saved answers were loaded.

## Chosen implementation contract and target map

Normalize the Customer.io person's email for matching, select the newest supported quiz-kind row with saved answers using `(created_at DESC, id DESC)`, and write that exact lead ID into the credential record at issuance. Never resolve the URL from a mutable Customer.io `lead_id` trait or reselect by email on click. A new quiz completed after the email was generated does not change the already-sent link.
