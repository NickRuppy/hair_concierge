## 3. Damage signal
- There is no user-entered "damage level". Damage is DERIVED in `src/lib/personal-plan/needs.ts` `buildDamageAssessment` (L100-160): `PlanDamageAssessment {structuralLevel none|low|moderate|high|severe, chemicalStress 0-4, heatLevel, mechanicalLevel, repairPriority none|low|medium|high, structuralSignals...}`; score = surface(rough 4/uneven 2) + chemical (lightened 4 > straightened 3 = colored+permed 3 > colored|permed 2) + concerns (breakage 4, hair_damage 3, split_ends 2, capped 5); level cut-offs 0 none, 1 low, 2-3 moderate, 4-5 high, 6+ severe (L40-47). `low` is unreachable in practice (smallest nonzero step is 2).
- Raw inputs (diagnostics JSONB): `chemicalTreatments` [natural|colored|lightened|permed|chemically_straightened], `currentConcerns` [..., hair_damage, breakage, split_ends, ...], `hairSurface` [smooth|slightly_uneven|rough], `elasticResponse` [stretches_bounces|stretches_stays|snaps]. Collected in the quiz (V3), stored in `hair_profiles.diagnostics` via `user_facts_save_v1`; snapshot carries `profile` + `assessments.damage` (`InitialNeedPlanSnapshot`, `types.ts` L531-545).
- Consumer matrix:
  - (i) Bondbuilder category decision: PASSED (raw facts; tier basis/optional + inclusion rule id). Tier is NOT a damage band; `damage` arg only used for heat reason.
  - (ii) `Stage3AuthorityInput` (`authority/contracts.ts` L203-232): NOT passed as damage. It carries `hairThickness`, `coverage`, and `categoryDecision` (a `PlanCategoryDecision` whose `reasons[]` include `bondbuilder.inclusion.*` and `bondbuilder.reason.*` ids) -> the damage story is reachable only via reason ids. The full snapshot (`assessments.damage`) is in scope at `product-previews.ts` L117/255 (`input.snapshot`), `discovery/equal-options.ts` L55, `production-persistence-gateway.ts` L516 (`context.refinedNeedSnapshot`), but NOT at `scan/resolve-verdict.ts` (`BuildScanVerdictInput` has `decision`, no snapshot; also built by `product-intake/scan-catalog-readiness.ts` L312, `scan/load-scan-verdict.ts` L114, `mobile/scan-service.ts` L355).
  - (iii) Cadence builder `routine/cadence.ts` `resolveRoutineItemCadence` (L165-): NOT passed. Pure function of `{category, role, productId, recommended, userOverride, authorityFacts[{productId,category,role,cadence}]}`; reads only `fact.cadence` and accepts bondbuilder kinds `label_course|label_schedule|frequency|weekly_range|wash_event` with non-blank `copy_de` (L58-72); anything else -> "Nach Herstellerangabe" + gap `exact_product_cadence_unavailable` (L196-206). Call sites: `routine-candidate-compiler.ts` L307 (has `decision` incl. reasons) and `routine/source-sync-service.ts` L183 (successor sync; only has the compiled item, whose `authorityRuleIds` L338-343 persist `decision.reasons[].id`). Resolved cadence is persisted into the routine payload (`cadence.resolved`), so a damage-dependent copy implies recompute/successor on damage change.

Concerns hair_damage 45, breakage 26, split_ends 33. Surface rough 32 / slightly_uneven 113 / smooth 31. Elasticity snaps 30 / stretches_stays 47 / stretches_bounces 100. ## 4. Cadence branching
- Aveda (04a83f16) `product_bondbuilder_specs.research_profile.application.cadence` (path is `application.cadence.value`; there is no top-level `cadence` key; top-level keys: fit, holds, method, review, formula, sources, version, evidence, identity, assessment, application, explanations_de, technology_reference):

Schema: `src/lib/bondbuilder-research/contracts.ts` L183-203 (status enum source_stated|source_stated_conditional|not_stated|conflicting; clause kinds times_per_week | every_n_washes | consecutive_washes). Conditions are free-text English notes, not an enum.
- Chain that drops it: `bondbuilder-research/cadence-projection.ts` L19 returns null when `value.status !== 'source_stated'` or `branches.length`; `catalog-enrichment/bondbuilder-reviewed-promotion.ts` hard-codes `cadence: null` (L50/113/220; also in the ANCILLARY set L27); so `product_application_protocols.cadence` for Aveda = NULL and the plan shows "Nach Herstellerangabe" + `exact_product_cadence_unavailable`. `protocol-projection.ts` L228/L505 also treat branches as a hold for protocol resolution.
- Cadence JSON "schema": no DB CHECK on `product_application_protocols.cadence` (only JSONB). Kinds in use in prod: bondbuilder label_course(1) label_schedule(3); shampoo label_schedule/label_suitability/wash_event; mask label_schedule/daily(legacy `{type,source}`); oil frequency/as_needed; scalp_care daily/daily_or_twice_daily_as_needed/label_timing/weekly_range; deep cleansing weekly_range/label_daily_suitable; conditioner label_suitability/as_needed. Runtime accepts per-category allow-lists in `cadence.ts` L58-72. **No conditional/branch kind exists in any category** (no "bei Schuppen" style condition anywhere; scalp-care roles are keyed per role, not per user condition).
- Overlap warning: Aveda bands overlap at "moderate"; the app's levels are none/low/moderate/high/severe (47 prod profiles are exactly "moderate"; 73 severe; 39 high). A mapping (e.g. moderate -> ?) is a ruling, per the research profile's own limitation.
