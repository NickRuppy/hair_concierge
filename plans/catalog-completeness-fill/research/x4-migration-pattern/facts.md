## D. Reusable generator?

No shared manifest->SQL framework. Each migration has a bespoke generator: KM `plans/kevin-murphy-oil-migration/generate.ts` (best template: fingerprint, PRESTATE_CHECKS/FULL_RESTORE_CHECKS/TARGET_CHECKS, rollback, verify, manifest, `--check`) and `scripts/product-intake/bondbuilder/generate-reviewed-promotion-sql.mjs` (frozen-artifact serializer, `--check`). Reusable building blocks to import: `buildExpansionProtocolRow` + `EXPANSION_TEMPLATE_APPLICATION_FAMILY` (`src/lib/product-intake/expansion-apply-templates.ts`), `buildProductApplicationPointerV2` (`src/lib/product-intake/catalog-enrichment/stage5-v2-builder.ts`), `validateProductIntakeCategorySpecs` (`src/lib/product-intake/category-validators.ts`), `applicationGuidanceProtocolSchema` (`src/lib/routines/personal-plan/application/contracts.ts`), `catalogAuthorityValueFingerprint`/`assertCatalogAuthorityRepairReady` (`src/lib/catalog-authority/repair.ts`, fingerprint-bound manifest gate; the 2026-08-15 SQL predates it and its README says hand-written repair SQL is no longer accepted). Recommendation: one Slice-1 generator copying KM's structure, with one DO block per product group, a P08-style fresh-DB skip, and the extra generated-column skip list for identifiers.
