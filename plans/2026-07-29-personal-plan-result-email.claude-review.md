**High-confidence issues** (correctness, not preference)

- **B — Task 5's "copy" has no proven mechanism.** The operator script only *updates* existing templates; targets are hard-coded numeric IDs validated in `parseCliOptions` (`customerio-quiz-result-email.ts:16-33, 201-211`). Copying transactional message `8` to a *new* message/template is unproven for `@customerio/cli@0.0.19`, and the new target can't be added to config until the copy yields IDs (chicken-and-egg the plan only half-acknowledges at line 314). **Owner decision:** confirm the CLI supports a copy/create call, or copy in the Customer.io UI first and then run the guarded apply against the captured IDs. Also note subject/preheader live in the script *config*, not the HTML file (`customerio-quiz-result-email.ts:13-15`) — the new operator needs its own `"Dein persönlicher Haarplan ist bereit"` subject + preheader constants; Task 5 doesn't mention this.
- **C — recovery is strictly weaker than legacy, and the plan doesn't say so.** Legacy sends are client-triggered (`src/components/quiz/quiz-results.tsx:199`), so a failed/lost send can be re-POSTed by the browser. The personal-plan path fires only from server `after()` (plan Task 3). If the `after()` callback is dropped (serverless termination) or the claim sticks at `'sending'`, the email is silently lost with **no** client retrigger and **no** reaper — recovery waits for the deferred "replay adapter." The 1-hour artifact TTL (`personal-plan-prepare/route.ts:14`) bounds the missing-`primaryMessage` window but not this. **Owner decision:** is fire-and-forget acceptable at launch, or is a stuck-`sending` reaper / replay needed now?
- **New claim should filter `quiz_kind = 'personal_plan'`.** `artifact_email_status` is a single shared column; the legacy claim scopes itself with `.eq("quiz_kind","legacy")` (`route.ts:164`). Task 2 says only "claim `artifact_email_status IS NULL`" — mirror the kind filter so the personal-plan claim can never touch a legacy lead.
- **Use `npm run ci:verify`, not `typecheck`+`lint` alone.** The plan's Verification (lines 273-275) omits `build`. This adds a new route wiring, new files, and an additive type change to `PersonalPlanPublicOfferModel` — run the project's own gate (`package.json:20`).
