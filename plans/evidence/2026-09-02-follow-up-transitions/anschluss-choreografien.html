Skelett-Dialekte vereinheitlichen

Two skeleton styles coexist across the app today — some routes pulse (Routine, Anwendung), others are static grey (Chat, Tracker, Profil). Navigating between them reads as a stutter. One dialect should win.

Entscheidung 5 · which dialect?

Static grey

The documented “neutral shell” contract. Calm, no motion competing with content, cheapest to render.

Recommended app-wide — animated loading stays reserved for journey moments (the opening frames above).

Pulsing

Signals liveliness, but adds motion everywhere and currently exists on only two routes.

Only if you prefer it — then it must be applied everywhere for consistency.

Scope note: Follow-up A reuses the shipped plan-opening CSS plus the existing PersonalPlanStageEntrance/PersonalPlanViewTransition machinery — no backend changes. Follow-up B touches the reveal component and adds a loading shell for /result/[leadId]; the fixed 3-sentence timing of the reveal itself stays untouched.
