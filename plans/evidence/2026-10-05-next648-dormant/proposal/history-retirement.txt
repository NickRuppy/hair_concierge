    Activate the complete Personal Plan journey (#382)
    
    ## Why
    
    The five-stage Personal Plan was merged but remained unavailable because
    its top-level and Stage 5 launch flags were empty, and the reviewed V2
    application catalog had never been applied. Stage 5 also still had a
    runtime V1/V2 fork after its canonical instructions were approved.
    
    ## What changed
    
    - Retire the obsolete Personal Plan app and Stage 2–5 launch flags;
    eligible owners now follow the released five-stage journey by default.
    - Make Anwendung use the V2 contract exclusively, with shared canonical
    family instructions for ordinary products and exact steps only for the
    five reviewed workflows.
    - Remove the duplicate generic label-time caution when a targeted
    shampoo already renders its reviewed timing.
    - Add a service-role-only, atomic, idempotent V2 artifact executor plus
    guarded operator apply/readback tooling.
    - Preserve the new-buyer cutoff, legacy-quiz cutover, owner
    authorization, and initial-Routine write gate as real independent
    boundaries.
    
    ## Verification
    
    - `npm run typecheck`
    - `npm run test:node` — 3,624 passed before rebasing onto PR #381
    - `npm run test:personal-plan` — 1,259 passed before rebasing onto PR
    #381
    - `npm run test:personal-plan-stage5` — 193 passed on current head
    - `npm run lint` — no errors; four pre-existing warnings
    - `npm run build` — 125 pages built on current head
    - `npm run personal-plan:application-audit` — 273 rows, 272 composable,
    one explicit blocker
    - Live read-only preflight — zero blockers across 224 products / 273
    roles
    - Production migration `20260813060630` applied
    - Production artifact first apply and exact retry both returned 23
    families / 273 pointers / 273 ledger rows with exact readback
    - Independent Claude whole-branch review; all blocking findings resolved
    
    ## Risks / follow-up
    
    - Rollback is revert-and-redeploy; V1 data remains intact for that path.
    - OLAPLEX No.0 remains the one explicit non-executable workflow until
    its real companion is verified.
    - Product Intake’s future-publication V2 invariant is an immediate
    separate follow-up so this activation remains independently revertible.
    - PR #381 intentionally removed Docker-backed pgTAP and persisted Stage
    4/5 browser harnesses. This branch preserves that deletion and relies on
    migration source contracts plus guarded production-first apply/readback.
