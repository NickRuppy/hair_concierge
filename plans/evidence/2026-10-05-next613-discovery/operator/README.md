## Mutation/rollback ownership

Shared lock: `/tmp/test-audit-pruning-operator-lock`; atomic mkdir plus unique owner token. Existing/stale locks are never cleared automatically. No other process is inspected or terminated. Mutation modes hold the lock throughout their operation and release only matching ownership.

Editor snapshots all24 originals before first repository write; driver snapshots all24 test originals and all4 unique owner originals before first child/fault, with unique backup/receipt directories and no-overwrite creation. Writes use before-byte CAS, unique same-directory temp, second CAS check and rename. Rollback only restores exact bytes this operation wrote; concurrent bytes are preserved with original backups/failure receipt. Editor rechecks guards after rollback; driver restores in finally after assertion/error/timeout/interruption and rechecks every guard before restored clean run. Source fault and test editor cannot mix phases or unknown source overrides.

Each runtime child is detached, max45seconds. Only its owned process group is eligible for SIGKILL on timeout/interruption/cleanup. No source write occurs while that child is running. Process-group cleanup intentionally follows exit to stop a child-owned descendant, never another task's process. SIGKILL of the operator itself cannot execute JS finally; in that case the retained lock, backups and hashes require main inspection. No implementation can guarantee rollback against abrupt OS/process death; do not force-clear the lock.
