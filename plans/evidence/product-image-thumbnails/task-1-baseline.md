# Task 1 image-loading baseline

Date: 2026-08-15

## Scope and method

- Surface: local Personal Plan Stage 3 lab, using the exact two Sante product names and exact canonical production Storage URLs from the reported search.
- Production limitation: the available production browser session redirected to account reactivation because it had expired, so this is not an authenticated production-journey measurement. The lab isolated the image-loading interval while requesting the real production image assets.
- Browser cache: disabled for cold runs; enabled for the warm control.
- Network profile: 150 ms latency, 200,000 bytes/s download, 93,750 bytes/s upload (about 1.6/0.75 Mbps).
- Timing: result text and `HTMLImageElement.complete`/`naturalWidth` were polled every 25 ms. CDP Network events supplied response, transfer, byte, and cache-header evidence.
- Each reported median uses three valid runs. Test-only fixture and component edits were reverted.

## Results

| Lane | Image lag after result text (ms) | Median | Slowest-object transfer | Bytes per two-image result |
| --- | --- | ---: | --- | ---: |
| Canonical 1200x1200, cold browser cache, CDN HIT | 482, 500, 489 | **489 ms** | 472-479 ms for the 37.6 KB image | about 62.1 KB |
| Canonical plus `width=48`, `height=48`, `decoding=async`, cold | 502, 509, 504 | **504 ms** | 477-501 ms for the 37.6 KB image | about 62.1 KB |
| Canonical, warm browser cache | 0, 0, 0 | **0 ms** | 0 ms / 0 transferred bytes | 0 bytes |
| Supabase 144x144 transform, cold browser cache, CDN HIT | 212, 202, 173 | **202 ms** | 168-181 ms | about 3.6 KB |

Both canonical responses were Cloudflare `HIT`s with `cache-control: public, max-age=31536000`. Their encoded response sizes were about 37.6 KB and 24.6 KB. The 144x144 transformed responses were about 1.86 KB and 1.70 KB, a roughly 94% reduction for this pair.

The first request for each newly transformed URL was a CDN `MISS`: the two images completed about 614 ms after result text. Once cached at the edge, the median was 202 ms. This cold-transform penalty is why the proposed common search variant should be generated and stored ahead of use rather than first generated by an end-user request.

## Decision

**Proceed.** The current cold-cache median is 489 ms after result text, above the plan's 300 ms stop/go threshold. The attribute-only control did not improve it and was slightly slower within normal run variance. A small-asset CDN-HIT control improved the median by 287 ms (about 59%), exceeding the 200 ms target for the eventual after measurement.

The evidence supports the existing two-asset direction:

1. retain the 1200x1200 canonical product image for larger presentation surfaces;
2. pre-generate and store the common 144x144 search thumbnail before it can be requested;
3. serve the thumbnail in 48px Stage 3 cards, with canonical fallback.

Supabase documents on-the-fly transformations but also recommends pre-generating common variants, leveraging Smart CDN caching, and controlling browser cache duration. Image transformations on Pro/Team include 100 origin images per billing period and then use package billing, which is another reason not to make transformation the catalog's required runtime path.

## Remaining verification

After implementation, repeat this profile against the authenticated production journey and the stored thumbnail URLs. Do not claim production improvement until the matched after-run confirms at least 200 ms median improvement with no reproducible regression.
