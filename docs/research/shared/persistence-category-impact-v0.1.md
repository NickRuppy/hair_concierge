# Canonical persistence: category impact map

2026-10-09. This maps research and consumer changes; only oil integration is authorized in this slice. The [shared definition](persistence-potential-v0.1.md) owns `persistence_potential: low | moderate | high`. One committed scalar; reasons and source evidence remain outside computation. Persistence describes likely conditioning-coating persistence in the stated application context, not measured accumulation over repeated washes or sensory weight.

| Category | Current meaning and migration needed | Consumers that need review | Current action |
| --- | --- | --- | --- |
| Oil | Replace `build_up_potential: low/elevated` with canonical persistence. Rejudge complete formulas; ordinary retained oil can be moderate. Do not rename old labels. | Property set, classification standard, operating guide, future research records/projection. The binary material reference remains historical, not an active value prior. | Integrate locally and replay existing admitted declarations. No production adapter exists yet. |
| Leave-in | Current `persistence_removal_class` is a mechanism class and the profile derives persistence from it. Canonical persistence would instead judge the whole conditioning system. Keep exact charge/mechanism facts in research evidence; consumers needing charge must still use charge facts, not infer charge from low/moderate/high. | [Standard §7.6 and §8 cautions](../leave-in-inci/v1.0/leave-in-classification-standard.md), prompt, runbook, profile schema/projection, adapter AD-4 conditioner relationship and intake bridge. High persistence is not synonymous with permanent cationic charge. | Future separate migration with calibration and adapter compatibility checks; native behavior unchanged here. |
| Conditioner | Current `cumulative_residue_risk: lower/indeterminate/higher` explicitly needs repeated-cycle evidence. Canonical post-rinse coating persistence is a different endpoint. Add canonical persistence to the research contract; if it replaces a computational residue proxy, retire that proxy explicitly. Preserve actual accumulation evidence separately rather than rename it. | [Standard direct-properties table](../conditioner-inci/v1.0/conditioner-classification-standard.md), prompt, agent context, quick reference, runbook, matching/projection/adapter bridge only where they actually consume a residue field. Current production adapter has no direct `cumulative_residue_risk` reader found in this checkout. | Future separate research/consumer migration. Never convert indeterminate to moderate. |
| Shampoo | Already considers persistence together with deposition load and reset capacity to decide `weightPotential`. This is not a stand-alone equivalent of the proposed property. | [Shampoo v1.4 weight method](../shampoo-inci/v1.4/classification-standard.md), weight assessment trace, guides/projection only if later harmonized. A persistent constituent cannot override shampoo cleansing/reset architecture. | Leave unchanged. A later harmonization must preserve whole-shampoo reset/deposition semantics and recalibrate weight. |
| Mask / other conditioning categories | Reuse the shared definition when the category contract admits this endpoint, with its actual rinse/retention context. Do not add a field solely for schema uniformity. | Their own versioned standard and any adapter when present. | No category or runtime change in this slice. |

The six-case [compatibility pilot](../../../data/research/shared/persistence-pilot-v0.1/results-for-review.md) demonstrates that the three classes can be applied across rinse-out and retained products. Agreement is repeatability, not validation. For example, native leave-in mechanism-to-profile logic produced moderate on the Balea spray while the new whole-formula pilot chose low; this can change adapter AD-4 behavior and therefore must not be slipped into a documentation-only sibling migration.

Oil integration does not add another thickness/damage/pattern penalty or infer cleansing frequency, safety, growth, repair, measured washout, or universal suitability. Source identity and exact declaration problems remain admission errors, not an extra persistence output value.
