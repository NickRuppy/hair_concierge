# Bondbuilder v0.5 runbook

Release candidate procedure for the authorized bounded finish; lock/activation are separately recorded decisions. Normative rules: [standard](standard.md); synchronized [researcher prompt](researcher-prompt.md) and [blind guide](blind-instructions.md). Frozen historical v0.1–v0.4 remain untouched.

1. Create a new run, refusing existing output. Freeze all four method documents, strict schema, exact identities/formulas, anonymous and named source packets, minimal owner/default and technology-reference packets, preregistered cohort/metrics and all hashes. Verify original source bytes against lineage. Document source/normalization/version changes.
2. Distinguish eight-pilot calibration regression, four known-outcome replay and synthetic contracts; none is a new holdout. A wider requested coverage branch requires additional newly frozen identities, not relabeling these. The owner decides whether the disclosed bounded coverage supports lock.
3. Run two fresh-context anonymous lanes with only the blind guide/prompt/packet. Collect actual file read hashes/incidents and seal BOTH before named release.
4. Release identical named packet/standard/schema/policy/reference inputs to both lanes. Extract complete producer facts, evidence scope, unknowns, independent fit and holds. Policies apply only to exact identity/formula binding. No web or peer/old label access.
5. Mechanically attach exact frozen metadata/sources and compute hashes; assembly cannot change model facts, fill missing research or confer authority. Strictly validate each profile. Ineligible/review cases remain retained research with projection refusal; new eligible cases remain low/default and non-recommended. Compare both raw and assembled records; source IDs and contradictions must remain visible.
6. Seal both named outputs before mechanical comparison. Adjudicate value/wire/confidence/source discrepancies explicitly. Any source correction gets a new amendment receipt/replay, not modified sealed packets or an inflated unseen count.
7. Verify full profile retention, source closure, exact whole pin tuple, raw/list/self digest, owner/default authority, candidate traces and historical byte preservation. Execute actual adapter/CLI and edge tests; report readiness separately and preserve unknown protocols/fit.
8. Write measured findings and, only after explicit coverage acceptance plus actual success, a lock receipt naming exact hashes/limitations. Update index/router/bridge to actual status. Historical profiles may use exact historical pins; new prepared intake uses current release. No mixed-version pin acceptance.
9. Before any live activation: verify migration lineage/schema/readback, exact product/source bindings and consumer/worker integration, then obtain/record the explicit activation decision. Catalogue publish/promotion/deployment remain their own guards. No Docker or production test seeding is part of this run.
